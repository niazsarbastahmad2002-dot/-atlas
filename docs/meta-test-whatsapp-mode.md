# Atlas Meta WhatsApp test mode

Atlas can exercise its WhatsApp transport against Meta's official Cloud API test phone number without touching the real +964 sender or clinic Coexistence records.

## Safety boundary

- `ATLAS_WHATSAPP_MODE=meta_test` selects only `WHATSAPP_TEST_*` credentials.
- Test mode is rejected when `VERCEL_ENV=production`.
- Meta's official test WABA itself limits delivery to recipients registered in Meta. `WHATSAPP_TEST_ALLOWED_RECIPIENTS` is an optional extra Atlas-side E.164 restriction.
- Existing production `WHATSAPP_*` credentials and clinic-scoped Coexistence rows are never overwritten by this mode.
- `/api/whatsapp/test/bootstrap` and `/api/whatsapp/test/send` are non-production-only and require `WHATSAPP_TEST_ADMIN_SECRET`.
- The production reminder cron is never repointed at the test sender.

## Required test assets

Configure only in a non-production environment:

```env
ATLAS_WHATSAPP_MODE=meta_test
WHATSAPP_TEST_ENABLED=true
WHATSAPP_TEST_ACCESS_TOKEN=<Meta test token>
WHATSAPP_TEST_PHONE_NUMBER_ID=<Meta test phone-number ID>
WHATSAPP_TEST_WABA_ID=<Meta test WABA ID>
```

Optional extra restrictions or advanced webhook tests:

```env
WHATSAPP_TEST_GRAPH_API_VERSION=v25.0
WHATSAPP_TEST_GLOBAL_DAILY_LIMIT=100
WHATSAPP_TEST_ALLOWED_RECIPIENTS=+9647XXXXXXXXX
WHATSAPP_TEST_APP_SECRET=<only for signed inbound-webhook testing>
WHATSAPP_TEST_VERIFY_TOKEN=<test webhook verify token>
WHATSAPP_TEST_ADMIN_SECRET=<random 24+ character secret for manual test endpoints>
```

Never copy the real +964 sender token or phone-number ID into the test variables.

## Verified transport

Atlas Preview has completed a real send through Meta's official test sender. Meta accepted the `hello_world` message and returned a WhatsApp provider message ID. This proves Atlas Preview → Meta Cloud API → registered test recipient transport while the production +964 sender remains untouched.

## Templates

Atlas requested the two Patient Loop reminder templates in Arabic and English:

- `atlas_visit_confirm_v1`
- `atlas_visit_today_v1`

Meta can leave new templates in `PENDING` while reviewing them. Atlas does not bypass review.

Production-intended support templates remain:

- `atlas_login_otp_v1` — AUTHENTICATION OTP template.
- `atlas_staff_invite_v1` — secure receptionist invitation link.

The Meta test WABA currently does not have the production eligibility needed to create the authentication template. A utility OTP test template was also rejected. Treat this as a provider limitation, not something to bypass.

## Login and signup OTP

Supabase remains the authentication authority. Atlas never creates or verifies its own OTP.

Supabase's Send SMS Hook calls `/api/auth/send-sms-hook`. Atlas verifies the Standard Webhooks signature and transports the six-digit OTP generated by Supabase. The user submits that same code to the existing Supabase `verifyOtp(..., type: "sms")` flow.

Production OTP remains template-only. In `meta_test` only, if the test WABA cannot use the authentication template, Atlas can fall back to a plain WhatsApp text containing the Supabase-generated OTP. That test fallback only works inside Meta's official 24-hour customer-service window after the registered test recipient messages or replies to the test sender. It is never used by the production sender.

Hosted Supabase Phone Auth and the Send SMS Hook still need to be enabled for the non-production OTP exercise.

## Receptionist invitations

The existing invitation remains a secure one-use server-generated token that expires after 24 hours and is redeemed through `/join/<token>`.

In `meta_test`, the Staff page automatically exposes the recipient field after the safe test health check succeeds. Atlas first attempts the approved-template delivery path. If the test WABA lacks the custom invitation template, it may fall back to plain text only inside Meta's 24-hour test conversation window. Production remains template-only and clinic-scoped to the real Coexistence sender.

## Appointment reminders

The protected `/api/whatsapp/test/send` dispatcher uses the same Meta payload builder as Atlas reminders without consuming or mutating the production reminder queue. The two Patient Loop templates must be approved by Meta before those exact reminder templates can be sent from the test WABA.

## Promotion rule

Never merge test credentials into Git, never add them to production environment variables, and never set `ATLAS_WHATSAPP_MODE=meta_test` in production. Before enabling production OTP or direct staff delivery, require approved production templates, a real authorized sender, successful Supabase OTP verification, rate-limit tests, and the normal Atlas release gate.
